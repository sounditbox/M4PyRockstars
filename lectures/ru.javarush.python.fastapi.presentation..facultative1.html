Факультатив: ручной деплой

Локальное приложение доступно только разработчику. После деплоя у приложения появляется публичный адрес, который можно передать другим людям.

На занятии мы откроем локальный FastAPI через ngrok, познакомимся с облачными платформами и вручную запустим приложение на виртуальном сервере Yandex Cloud.

От локального запуска к серверу

Во время разработки приложение запускается на нашем компьютере и слушает localhost. Такой адрес недоступен другим пользователям через интернет.

При деплое мы повторяем запуск в другом окружении: на облачной платформе или удалённом Linux-сервере. Сервер получает публичный адрес и принимает внешние HTTP-запросы.

Локальный запускПосле деплоя
Приложение работает на компьютере разработчикаПриложение работает на удалённом сервере
Адрес localhostПубличный URL или IP-адрес
Настройки хранятся в локальном .envНастройки передаются в окружение сервера
Процесс можно остановить вместе с терминаломПроцесс должен продолжать работать без разработчика
Деплой не изменяет назначение приложения. Он переносит конкретную версию кода в окружение, доступное пользователям.

Как устроен ручной деплой

Скопировать исходники недостаточно. На сервере нужно заново подготовить всё, от чего зависит приложение.

Ручной деплой обычно состоит из следующих шагов:

  1. Получить нужную версию кода.
  2. Установить Python и зависимости проекта.
  3. Добавить переменные окружения и секреты.
  4. Подготовить базу данных и выполнить миграции.
  5. Запустить приложение на доступном порту.
  6. Разрешить входящие соединения в сетевых настройках.
  7. Проверить приложение с другого компьютера.

На VPS эти действия выполняет разработчик. Render и другие PaaS-платформы автоматически получают код, устанавливают зависимости и запускают процесс.

Деплой считается завершённым не после успешной команды запуска, а после внешней проверки публичного адреса. Для этого у приложения есть health endpoint.

Секреты не добавляют в Git. Пароли, токены и ключи передают через серверный .env или настройки облачной платформы.

Вариант 1: ngrok

ngrok создаёт публичный адрес и пересылает запросы на локальный порт.

graph LR USER[Пользователь] --> URL[Публичный URL ngrok] URL --> API[FastAPI на localhost:8000]

Запустите зависимости проекта, миграции и FastAPI:

docker compose up -d --wait postgres mongo redis rabbitmq
uv run alembic upgrade head
uv run uvicorn app.main:app --host 127.0.0.1 --port 8000

В другом терминале запустите туннель:

ngrok config add-authtoken <YOUR_AUTHTOKEN>
ngrok http 8000

Откройте выданный адрес:

https://example.ngrok.app/docs
https://example.ngrok.app/api/v1/health
ngrok — не сервер. Если выключить компьютер, Uvicorn или ngrok, публичный адрес перестанет работать. Через туннель открываем только FastAPI, но не порты баз данных.

Вариант 2: Render

Render забирает код из GitHub, устанавливает зависимости, запускает FastAPI и выдаёт HTTPS-адрес.

  1. Отправьте проект в репозиторий GitHub.
  2. В Render создайте New → Web Service и подключите репозиторий.
  3. Выберите бесплатный тип сервиса.
  4. Заполните команды сборки и запуска.
Настройка RenderЗначение
LanguagePython 3
Build Commanduv sync --frozen
Start Commanduv run alembic upgrade head && uv run uvicorn app.main:app --host 0.0.0.0 --port $PORT

Добавьте переменные окружения:

DEBUG=false
JWT_SECRET_KEY=replace-with-a-long-random-secret
DATABASE_URL=sqlite+pysqlite:///./products.db

После деплоя проверьте адрес https://YOUR_SERVICE.onrender.com/api/v1/health.

Это учебный вариант. Бесплатный Render засыпает после 15 минут без запросов, а локальный файл SQLite может исчезнуть после остановки или нового деплоя. Для постоянных данных нужна внешняя база.

Вариант 3: Yandex Cloud VM

Yandex Compute Cloud предоставляет виртуальную машину. Здесь мы сами устанавливаем программы и запускаем приложение.

Yandex Cloud не является постоянно бесплатным. Новым клиентам доступен стартовый грант на 60 дней. Размер гранта зависит от страны, а после его окончания ресурсы оплачиваются по тарифу.

1. Создаём сервер

  1. Создайте платёжный аккаунт и проверьте стартовый грант в Yandex Cloud Billing.
  2. Откройте Compute Cloud → Виртуальные машины → Создать ВМ.
  3. Выберите Ubuntu 24.04 LTS и назначьте VM публичный IPv4-адрес.
  4. Укажите имя пользователя и добавьте свой публичный SSH-ключ.
  5. В группе безопасности разрешите TCP-порт 22 для SSH и 8000 для FastAPI.
  6. Сохраните имя пользователя и публичный IP.

SSH-ключ создаётся на вашем компьютере:

ssh-keygen -t ed25519

2. Подключаемся

ssh USERNAME@SERVER_IP

На сервере установите Git, curl и uv:

sudo apt update
sudo apt install -y git curl
curl -LsSf https://astral.sh/uv/install.sh | sh
source "$HOME/.local/bin/env"
uv python install 3.14

3. Запускаем FastAPI

git clone REPOSITORY_URL products-api
cd products-api
uv sync --frozen
nano .env

Для первого запуска достаточно минимального .env:

DEBUG=false
JWT_SECRET_KEY=replace-with-a-long-random-secret
DATABASE_URL=sqlite+pysqlite:///./products.db

Примените миграции и запустите приложение:

uv run alembic upgrade head
nohup uv run uvicorn app.main:app --host 0.0.0.0 --port 8000 > app.log 2>&1 &

Теперь API доступен с вашего компьютера:

http://SERVER_IP:8000/docs
http://SERVER_IP:8000/api/v1/health

Если приложение не открылось, проверьте процесс и журнал:

ps aux | grep uvicorn
tail -n 50 app.log
Это минимальный учебный деплой, а не production. Здесь пока нет домена, HTTPS, автоматического перезапуска и резервных копий. SQLite выбран, чтобы практика не превратилась в настройку нескольких баз и очередей.

Практика

  1. Запустите Products API локально.
  2. Откройте Swagger UI через ngrok.
  3. Опубликуйте упрощённый API на Render.
  4. Создайте Yandex Cloud VM и подключитесь к ней по SSH.
  5. Запустите FastAPI на VM и откройте health endpoint по публичному IP.

Что важно запомнить

  • ngrok временно открывает локальное приложение.
  • Render сам запускает приложение из GitHub, но ограничивает бесплатный сервис.
  • Serverless-платформы удобны для одного API, но не заменяют VPS.
  • На виртуальном сервере всё устанавливает и запускает разработчик.
  • Бесплатный тариф подходит для учёбы, но не гарантирует работу production-системы.
  • После любого деплоя нужно проверить health endpoint.
