Лекция 1: Введение в FastAPI и первый REST API

FastAPI — современный Python-фреймворк для создания HTTP API. Он опирается на стандартные аннотации типов Python, Pydantic для валидации данных и ASGI-серверы вроде Uvicorn для обработки запросов.

В этой лекции мы соберем первый рабочий API: настроим окружение, запустим приложение, разберем маршруты, параметры пути и запроса, модели Pydantic v2, валидацию входных данных, ответы через response_model, обработку ожидаемых ошибок и автоматическую документацию OpenAPI.

Студенты уже знакомы с Python, ООП, архитектурой веб-приложений, Docker и SQL, поэтому мы не будем долго объяснять HTTP с нуля. Вместо этого сразу свяжем известные backend-концепции с тем, как они реализуются в FastAPI.

Что такое FastAPI

FastAPI — это веб-фреймворк на Python для создания API. Его сильная сторона — не магия, а удачная связка нескольких зрелых идей:

  • type hints: аннотации типов описывают контракт данных прямо в коде.
  • Pydantic: проверяет, преобразует и сериализует данные по этим типам.
  • Starlette: дает ASGI-основу, маршрутизацию, middleware, request/response-объекты.
  • Uvicorn: запускает приложение как ASGI-сервер.
  • OpenAPI: документация генерируется из реального кода, а не ведется вручную отдельно.

FastAPI особенно удобен для JSON API, микросервисов, backend-for-frontend, внутренних сервисов, интеграций и приложений, где важны явные контракты данных.

Важно

FastAPI не делает приложение быстрым автоматически. Производительность зависит от БД, сетевых вызовов, блокирующего кода, количества воркеров, индексов и архитектуры. Фреймворк просто дает хорошие инструменты, чтобы не мешать этим частям работать эффективно.

Как запрос проходит через FastAPI

Один HTTP-запрос проходит через ASGI-сервер, приложение FastAPI, маршрутизацию, валидацию входных данных, ваш код и сериализацию ответа.

На первой лекции мы работаем с самым важным путем: request -> endpoint -> response. Middleware, зависимости, база данных и lifespan будут разобраны позже.

FastAPI, Django и Flask

Сравнение полезно не для спора "кто лучше", а чтобы понимать область применения.

Критерий Django Flask FastAPI
Типичный фокус полноценные сайты, админка, ORM, шаблоны легкие приложения и гибкие прототипы API-first приложения и сервисы
Структура много соглашений из коробки минимум соглашений умеренно свободная структура
Валидация API Django REST Framework serializers обычно сторонние библиотеки Pydantic-модели и type hints
Документация нужна настройка DRF/schema tools нужна сторонняя настройка Swagger UI и ReDoc из коробки
Когда выбирать когда нужна большая готовая веб-платформа когда нужен маленький гибкий слой когда основной продукт — HTTP API

FastAPI не заменяет Django во всех случаях. Если нужна админка, шаблоны, встроенная ORM и монолитная платформа, Django часто быстрее. Если нужен компактный typed API, FastAPI обычно удобнее.

Установка и запуск

Современный удобный вариант для старта — использовать uv. Он сам создаст локальное окружение .venv и будет запускать команды внутри него, поэтому активировать окружение вручную не нужно.

Инициализация проекта и установка зависимостей:

uv init fastapi-intro
cd fastapi-intro
uv add "fastapi[standard]"

Запуск в разработке:

uv run fastapi dev main.py

Если CLI недоступен или вы хотите явно указать ASGI-приложение, можно использовать Uvicorn напрямую:

uv run uvicorn main:app --reload
  • uv init — создает новый Python-проект.
  • uv add — добавляет зависимость в проект и фиксирует ее в pyproject.toml/uv.lock.
  • uv run — запускает команду в окружении проекта без ручной активации .venv.
  • fastapi dev — удобная команда для локальной разработки с auto-reload.
  • fastapi run — команда для запуска приложения без dev-режима.

Минимальное приложение

Создайте файл main.py. Это минимальный API с двумя GET-эндпоинтами.

from fastapi import FastAPI

app = FastAPI()


@app.get("/")
def read_root():
    return {"message": "Hello, FastAPI!"}


@app.get("/health")
def healthcheck():
    return {"status": "ok"}

Откройте в браузере:

  • http://127.0.0.1:8000/ — обычный JSON-ответ.
  • http://127.0.0.1:8000/health — простой health-check.
  • http://127.0.0.1:8000/docs — Swagger UI.
  • http://127.0.0.1:8000/redoc — ReDoc.
Термин

Функция, привязанная к HTTP-методу и пути, называется path operation function. В разговорной речи часто говорят "эндпоинт".

Path parameters

Path parameters — динамические части URL. Они объявляются в пути через фигурные скобки и приходят в функцию как аргументы.

from fastapi import FastAPI

app = FastAPI()


@app.get("/products/{product_id}")
def get_product(product_id: int):
    return {"product_id": product_id}


@app.get("/users/{username}")
def get_user(username: str):
    return {"username": username}

FastAPI использует аннотации типов для автоматического преобразования и валидации:

  • GET /products/10 -> product_id станет числом 10.
  • GET /products/abc -> FastAPI вернет ошибку 422 Unprocessable Entity.

Для дополнительной валидации используйте Path и Annotated. Annotated позволяет оставить основной тип параметра обычным Python-типом (int), а рядом передать FastAPI дополнительные правила. Path говорит, что это именно параметр пути, и задает ограничения вроде ge=1.

from typing import Annotated

from fastapi import FastAPI, Path

app = FastAPI()


@app.get("/products/{product_id}")
def get_product(
    product_id: Annotated[int, Path(ge=1, description="ID товара")]
):
    return {"product_id": product_id}

Query parameters

Query parameters — параметры после ? в URL. Обычно они используются для фильтрации, поиска, сортировки и пагинации.

from typing import Annotated

from fastapi import FastAPI, Query

app = FastAPI()


@app.get("/products")
def list_products(
    search: Annotated[str | None, Query(min_length=2, max_length=50)] = None,
    limit: Annotated[int, Query(ge=1, le=100)] = 10,
    only_available: bool = True,
):
    return {
        "search": search,
        "limit": limit,
        "only_available": only_available,
    }

Примеры запросов:

  • /products — все параметры берутся по умолчанию.
  • /products?search=phone&limit=20 — поиск и лимит.
  • /products?only_available=false — FastAPI преобразует строку в bool.

Query работает похоже на Path, но применяется к query-параметрам. В примере search может быть строкой или None, а Query(min_length=2, max_length=50) добавляет правила валидации и описание в OpenAPI. limit получает числовые границы через ge и le.

Pydantic v2

Для регулярных выражений используйте параметр pattern, а не regex. Старое имя regex устарело.

Какие параметры может принимать эндпоинт

Функция-эндпоинт может получать данные из разных частей HTTP-запроса. FastAPI определяет источник параметра по имени в пути, типу, значению по умолчанию и специальным функциям вроде Query, Path, Header, Cookie, Form, File и Depends.

Источник Как объявляется Пример запроса
Path product_id: int в пути /products/{product_id} GET /products/10
Query limit: int = 10 или Query(...) GET /products?limit=20
Body Pydantic-модель: product: ProductCreate POST /products с JSON-телом
Header user_agent: Annotated[str | None, Header()] заголовок User-Agent
Cookie session_id: Annotated[str | None, Cookie()] cookie session_id=...
Form username: Annotated[str, Form()] HTML-форма или application/x-www-form-urlencoded
File file: Annotated[UploadFile, File()] multipart/form-data
Dependency user: dict = Depends(get_current_user) значение собирается зависимостью 
from typing import Annotated

from fastapi import Cookie, Depends, Header, Query


def get_current_user():
    return {"username": "alex"}


@app.get("/dashboard/{section}")
def dashboard(
    section: str,
    page: Annotated[int, Query(ge=1)] = 1,
    user_agent: Annotated[str | None, Header()] = None,
    session_id: Annotated[str | None, Cookie()] = None,
    current_user: dict = Depends(get_current_user),
):
    return {
        "section": section,
        "page": page,
        "user_agent": user_agent,
        "session_id": session_id,
        "current_user": current_user,
    }

На этой лекции подробно используем path, query и body. Headers, cookies, forms, files и dependencies появятся в следующих темах.

Request body и Pydantic

Для JSON-тела запроса удобно описывать контракт через Pydantic-модель. FastAPI сам прочитает JSON, создаст объект модели, провалидирует поля и передаст его в функцию.

Field используется внутри Pydantic-моделей для правил конкретного поля: минимальная и максимальная длина строки, числовые границы, описание для документации и значение по умолчанию. В примере name должен быть длиной от 3 до 80 символов, а price должен быть больше нуля.

from pydantic import BaseModel, Field


class ProductCreate(BaseModel):
    name: str = Field(min_length=3, max_length=80)
    price: float = Field(gt=0)
    description: str | None = None
    is_available: bool = True

Теперь модель можно использовать в POST-эндпоинте.

from fastapi import FastAPI, status
from pydantic import BaseModel, Field

app = FastAPI()


class ProductCreate(BaseModel):
    name: str = Field(min_length=3, max_length=80)
    price: float = Field(gt=0)
    description: str | None = None
    is_available: bool = True


@app.post("/products", status_code=status.HTTP_201_CREATED)
def create_product(product: ProductCreate):
    return {
        "message": "Товар создан",
        "product": product.model_dump(),
    }

model_dump() — актуальный способ Pydantic v2 преобразовать модель в словарь. В старом коде можно встретить .dict(), но в новых материалах лучше сразу использовать model_dump().

Схемы входа и выхода

В реальных API входная и выходная модели часто различаются. Например, клиент присылает название и цену, а сервер возвращает еще и id.

from pydantic import BaseModel, Field


class ProductCreate(BaseModel):
    name: str = Field(min_length=3, max_length=80)
    price: float = Field(gt=0)
    description: str | None = None
    is_available: bool = True


class ProductRead(BaseModel):
    id: int
    name: str
    price: float
    description: str | None = None
    is_available: bool

response_model заставляет FastAPI проверить и отфильтровать ответ. Это защищает API от случайной утечки лишних полей.

@app.get("/products/{product_id}", response_model=ProductRead)
def get_product(product_id: int):
    product_from_db = {
        "id": product_id,
        "name": "Keyboard",
        "price": 99.0,
        "description": None,
        "is_available": True,
        "internal_margin": 0.42,
    }
    return product_from_db

Поле internal_margin не попадет в JSON-ответ, потому что его нет в ProductRead.

HTTPException

Если ошибка ожидаемая и связана с запросом клиента, возвращайте ее через HTTPException: ресурс не найден, недостаточно прав, конфликт данных, неверный формат бизнес-данных.

from fastapi import FastAPI, HTTPException, status

app = FastAPI()

products_db = {
    1: {"id": 1, "name": "Keyboard", "price": 99.0, "is_available": True},
}


@app.get("/products/{product_id}")
def get_product(product_id: int):
    product = products_db.get(product_id)
    if product is None:
        raise HTTPException(
            status_code=status.HTTP_404_NOT_FOUND,
            detail="Товар не найден",
        )
    return product

FastAPI сам превратит исключение в HTTP-ответ с нужным статус-кодом и JSON-телом:

{
  "detail": "Товар не найден"
}

OpenAPI, Swagger UI и ReDoc

FastAPI строит OpenAPI-схему из маршрутов, типов, моделей Pydantic, статусов и метаданных.

  • /docs — Swagger UI, удобно тестировать запросы руками.
  • /redoc — ReDoc, удобно читать контракт API.
  • /openapi.json — машинно-читаемая схема API.

Метаданные приложения помогают сделать документацию понятнее.

app = FastAPI(
    title="Products API",
    description="Учебное API для первой лекции FastAPI",
    version="1.0.0",
)

Метаданные эндпоинта тоже попадают в документацию:

    "/products/{product_id}",
    response_model=ProductRead,

Мини-проект: Products API

Финальный пример объединяет все темы лекции. Это in-memory API без базы данных: данные исчезают при перезапуске сервера. Так проще сфокусироваться на FastAPI, а SQLAlchemy появится позже.

from typing import Annotated

from fastapi import FastAPI, HTTPException, Path, Query, status
from pydantic import BaseModel, Field

app = FastAPI(
    title="Products API",
    description="Учебное API для первой лекции FastAPI",
    version="1.0.0",
)


class ProductCreate(BaseModel):
    name: str = Field(min_length=3, max_length=80)
    price: float = Field(gt=0)
    description: str | None = None
    is_available: bool = True


class ProductRead(ProductCreate):
    id: int


products_db: dict[int, ProductRead] = {
    1: ProductRead(id=1, name="Keyboard", price=99.0),
    2: ProductRead(id=2, name="Mouse", price=49.0),
}
next_product_id = 3


@app.get("/", tags=["system"])
def read_root():
    return {"message": "Products API is running"}


@app.get("/health", tags=["system"])
def healthcheck():
    return {"status": "ok"}


@app.get("/products", response_model=list[ProductRead], tags=["products"])
def list_products(
    search: Annotated[str | None, Query(min_length=2, max_length=50)] = None,
    limit: Annotated[int, Query(ge=1, le=100)] = 10,
):
    products = list(products_db.values())
    if search is not None:
        products = [
            product for product in products
            if search.lower() in product.name.lower()
        ]
    return products[:limit]


@app.get("/products/{product_id}", response_model=ProductRead, tags=["products"])
def get_product(
    product_id: Annotated[int, Path(ge=1, description="ID товара")]
):
    product = products_db.get(product_id)
    if product is None:
        raise HTTPException(
            status_code=status.HTTP_404_NOT_FOUND,
            detail="Товар не найден",
        )
    return product


@app.post(
    "/products",
    response_model=ProductRead,
    status_code=status.HTTP_201_CREATED,
    tags=["products"],
)
def create_product(product_data: ProductCreate):
    global next_product_id

    product = ProductRead(id=next_product_id, **product_data.model_dump())
    products_db[next_product_id] = product
    next_product_id += 1

    return product

Для проверки откройте /docs, создайте товар через POST, затем получите список через GET.

Практика

Задания рассчитаны на 15-25 минут. Их можно делать прямо в Swagger UI и в коде main.py.

  1. Добавьте поле category в ProductCreate и ProductRead. Ограничьте длину от 2 до 40 символов.
  2. Добавьте query-параметр only_available в list_products.
  3. Добавьте эндпоинт DELETE /products/{product_id}. Если товара нет, верните 404.
  4. Добавьте эндпоинт PATCH /products/{product_id} с отдельной моделью ProductUpdate, где все поля опциональны.
  5. Проверьте, как меняется документация /docs после каждого изменения модели.
