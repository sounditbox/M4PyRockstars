Уровень 13: Celery — асинхронные задачи и планирование

Выполнение долгих или ресурсоёмких операций напрямую внутри основного потока API неизбежно приводит к блокировкам и ухудшению пользовательского опыта. Celery — это мощная распределённая очередь задач для Python, которая позволяет 'отдавать на сторону' такие операции для выполнения в фоновом режиме, сохраняя отзывчивость вашего API.

Мы разберём архитектуру Celery, состоящую из продюсера, брокера и воркеров, и настроим его минимальный запуск с Redis. Вы научитесь интегрировать Celery как с FastAPI, так и с Django, асинхронно ставить задачи в очередь и эффективно отслеживать их состояние.

Отдельно рассмотрим незаменимый инструмент мониторинга Flower и возможности планирования задач по расписанию с помощью Celery Beat, что позволит вам создавать масштабируемые и эффективные фоновые процессы.

Что такое Celery и зачем он нужен?

Celery — это распределенная очередь задач для Python. Проще говоря, это инструмент, который позволяет вашему основному приложению (FastAPI/Django) "отдавать на сторону" долгие или ресурсоемкие операции для выполнения в фоновом режиме.

Когда это нужно:

  • отправка email-уведомлений: API должен ответить "ОК" за миллисекунды, а не ждать 5 секунд, пока почтовый сервер обработает запрос.
  • обработка загруженных файлов: сжатие изображений, конвертация видео.
  • генерация отчетов: создание сложных PDF или Excel.
  • обращение к медленным внешним API.

Используя Celery, ваш API остается отзывчивым, а вся тяжелая работа выполняется отдельно, в фоновых процессах-воркерах.

Архитектура Celery

Система на Celery состоит из трех ключевых частей, взаимодействующих через брокера сообщений.

  1. Producer:

    • это ваше приложение (FastAPI/Django).
    • его задача — создать задачу и отправить ее посреднику.

  2. Message Broker:

    • это посредник, обычно Redis или RabbitMQ.
    • он принимает задачи от продюсера и хранит их в очереди.

  3. Worker:

    • это отдельный Python-процесс, который вы запускаете на сервере.
    • он постоянно следит за очередью, забирает из нее задачи и выполняет их.

(Опционально) Result Backend — место, куда воркеры могут сохранять результаты задач (часто тот же Redis).

Ваше приложение (B) быстро отдает задачу брокеру (C) и отвечает клиенту. Воркер (D) в это время независимо выполняет тяжелую работу.

Минимальный пример: первый запуск Celery

Шаг 1: Установка

pip install celery "redis[hiredis]"

Шаг 2: Создание файла с задачами (tasks.py)

from celery import Celery
import time

# 'tasks' — имя модуля, broker — URL к Redis
app = Celery('tasks', broker='redis://localhost:6379/0')

@app.task # Декоратор, превращающий функцию в задачу Celery
def add(x, y):
    time.sleep(5) # Имитация долгой операции
    return x + y

Шаг 3: Запуск воркера
В терминале, в папке с tasks.py, выполните:

# -A tasks: указывает на приложение Celery в файле tasks.py
celery -A tasks worker --loglevel=info

Воркер подключится к Redis и будет ждать задач.

Шаг 4: Вызов задачи (из другого терминала)

>>> from tasks import add

# .delay() — это асинхронный вызов. Он не ждет 5 секунд, а сразу возвращает объект AsyncResult
>>> result_object = add.delay(4, 6)
>>> print(result_object.id) # У каждой задачи есть ID
'a1b2c3d4-e5f6-...'

Интеграция Celery с FastAPI

Файл celery_app.py:

from celery import Celery

# Настраиваем брокер для задач и бэкенд для результатов
celery_app = Celery(
    "worker",
    broker="redis://localhost:6379/0",
    backend="redis://localhost:6379/1" # Лучше использовать другую базу Redis для результатов
)

@celery_app.task
def send_email_task(recipient: str, subject: str):
    import time
    time.sleep(10) # Имитация долгой отправки
    print(f"Письмо на {recipient} с темой '{subject}' отправлено.")
    return "Success"

Файл main.py:

from fastapi import FastAPI
from celery_app import send_email_task

app = FastAPI()

@app.post("/send-email/fast")
def send_email_fast_route(email: str):
# .delay() ставит задачу в очередь и не ждет ее выполнения.
# API ответит мгновенно.
send_email_task.delay(email, "Быстрый способ")
return {"status": "Задача по отправке email поставлена в очередь"}

Примечание: для очень простых фоновых задач в FastAPI есть BackgroundTasks, но Celery гораздо мощнее для продакшена, так как работает в отдельных, масштабируемых процессах.

Интеграция Celery с Django

Интеграция с Django требует более формальной настройки, чтобы Celery "знал" о настройках проекта.

Файл myproject/celery.py (рядом с settings.py):

import os
from celery import Celery

os.environ.setdefault('DJANGO_SETTINGS_MODULE', 'myproject.settings')
app = Celery('myproject')
# Загружаем конфигурацию из settings.py (переменные с префиксом CELERY_)
app.config_from_object('django.conf:settings', namespace='CELERY')
# Автоматически находим файлы tasks.py во всех приложениях
app.autodiscover_tasks()

Файл myproject/__init__.py:

# Гарантирует, что Celery приложение загрузится при старте Django
from .celery import app as celery_app
__all__ = ('celery_app',)

Файл myproject/settings.py:

# Настройки для Celery
CELERY_BROKER_URL = 'redis://localhost:6379/0'
CELERY_RESULT_BACKEND = 'redis://localhost:6379/1'
# ... другие настройки сериализации ...

Файл myapp/tasks.py:

from celery import shared_task

# @shared_task позволяет создавать задачи без прямого импорта экземпляра Celery
@shared_task
def add(x, y):
    return x + y

Отслеживание задач

Вызов .delay() возвращает объект AsyncResult, который позволяет отслеживать состояние задачи.

Атрибуты AsyncResult:

  • result.id: ID задачи.
  • result.status: статус (PENDING, STARTED, SUCCESS, FAILURE).
  • result.ready(): True, если задача завершена.
  • result.get(): блокирующий метод для получения результата. Если задача упала с ошибкой, .get() вызовет это исключение.
  • result.result: результат, если status == 'SUCCESS'.
  • result.traceback: traceback, если status == 'FAILURE'.

Эндпоинт для проверки статуса:

from celery.result import AsyncResult
from celery_app import celery_app # Импортируем экземпляр Celery

@app.get("/tasks/{task_id}")
def get_task_status(task_id: str):
    task_result = AsyncResult(task_id, app=celery_app)
    return {
        "task_id": task_id,
        "status": task_result.status,
        "result": task_result.result if task_result.ready() else None
    }

Мониторинг и логирование: Flower

Flower — это веб-интерфейс для мониторинга и управления Celery. Обязательный инструмент для любого продакшен-проекта.

Установка:

pip install flower

Запуск:

# Для FastAPI проекта
celery -A celery_app flower --port=5555

# Для Django проекта
celery -A myproject flower --port=5555

Возможности Flower (доступно по http://localhost:5555):

  • просмотр статусов задач в реальном времени.
  • мониторинг нагрузки на воркеры.
  • просмотр деталей задач (аргументы, результат, ошибки).
  • управление задачами (отмена, повторный запуск) и воркерами.

Flower подключается к брокеру и собирает информацию от воркеров, предоставляя вам единый интерфейс для мониторинга всей системы.

Планирование задач: Celery Beat

Celery Beat — это планировщик. Это отдельный процесс, который запускает задачи по расписанию, как cron в Linux.

Как работает:

  • вы определяете расписание для своих задач.
  • процесс beat в нужный момент отправляет задачу в брокер.
  • свободный worker забирает и выполняет задачу.

Способы задания расписания:

  1. В коде (через beat_schedule):

    # В файле celery_app.py
from celery.schedules import crontab
celery_app.conf.beat_schedule = {
    'send-report-every-morning': {
        'task': 'tasks.send_daily_report',
        'schedule': crontab(hour=8, minute=0), # Каждый день в 8:00
    },
}

  2. В базе данных (с django-celery-beat):

    • позволяет управлять расписаниями через админпанель Django.

Запуск (нужно 2 процесса + воркеры):

# Запуск воркеров
celery -A myproject worker -l info
# Запуск планировщика
celery -A myproject beat -l info
